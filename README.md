# Sri Lankan Dengue Case Prediction Using Machine Learning

**Applied Machine Learning assignment, M.Sc. in Artificial Intelligence, University of Moratuwa**

This project forecasts the number of dengue cases each of Sri Lanka's 26 RDHS (Regional Director of Health Services) divisions will notify **in the following week**. It uses official weekly surveillance data from the Epidemiology Unit, Ministry of Health. The project compares naive baselines, a linear model and tree ensembles (Random Forest, XGBoost, LightGBM, and an averaging ensemble), using a time-ordered rolling-origin evaluation. It then explains the selected model with **SHAP** (global and local) and **LIME** (local).

> **Read first:** the dataset contains only **10 weekly reports (2026 weeks 24-33)**, and two of them are unreliable at division level. All results describe one declining phase of a single season. See [`docs/dataset_limitations.md`](docs/dataset_limitations.md).

## Key results (held-out test weeks 32-33, 52 forecasts)

| Model | MAE (cases) | RMSE | WAPE % | R² | Skill vs persistence |
|---|---:|---:|---:|---:|---:|
| Persistence (next week = this week) | 40.5 | 69.4 | 32.2 | 0.85 | 0% |
| Moving average (2 wk) | 61.2 | 109.9 | 48.6 | 0.63 | -51% |
| National-trend naive | 23.0 | 38.6 | 18.3 | 0.95 | 43% |
| Ridge regression | 44.1 | 77.6 | 35.0 | 0.82 | -9% |
| Random Forest | 19.5 | 32.2 | 15.5 | 0.97 | 52% |
| XGBoost | 20.9 | 35.6 | 16.6 | 0.96 | 48% |
| **LightGBM (selected)** | **18.0** | **30.3** | **14.3** | **0.97** | **56%** |
| Ensemble (RF+XGB+LGBM) | 19.3 | 32.2 | 15.3 | 0.97 | 52% |

* LightGBM was chosen on **validation** MAE (weeks 30-31). The test weeks were not used for any decision.
* A large share of the gain comes from following the national trend. ML improves a further ~22% on the strong national-trend baseline.
* SHAP shows that the model relies on three things: last week's national growth (season phase), mean reversion of the division's own last change, and how far the division sits above its historical level.

The full tables are in [`reports/results/RESULTS.md`](reports/results/RESULTS.md) and the figures are in [`reports/figures/`](reports/figures/). Both are regenerated by the pipeline.

## How to run it in VS Code (Windows)

**Prerequisites:** Python 3.11, 3.12 or 3.13 ([python.org](https://www.python.org/downloads/), with "Add to PATH" ticked), VS Code, and Git.

1. **Get the code**
   ```powershell
   git clone https://github.com/thanujaD00/AML-Assignment.git
   cd AML-Assignment
   code .
   ```
   When VS Code asks, install the recommended extensions (Python, Jupyter).

2. **Create and activate a virtual environment** (VS Code menu *Terminal → New Terminal*):
   ```powershell
   py -3 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```
   If PowerShell blocks the activation script, run this once:
   `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
   Then press `Ctrl+Shift+P` → **Python: Select Interpreter** → choose `.venv`.
   To reproduce the exact package versions, use `pip install -r requirements-lock.txt`.

3. **Run the full experiment** (about 30-60 seconds):
   ```powershell
   python scripts/run_pipeline.py
   ```
   This writes all tables to `reports/results/`, all figures to `reports/figures/`, and the trained models to `models/`.
   You can also open the **Run and Debug** panel (`Ctrl+Shift+D`) and choose **Run full pipeline**.

4. **Open the notebook:** open `notebooks/dengue_prediction.ipynb`, pick the `.venv` kernel (top right), then click **Run All**. The notebook runs the same pipeline and explains every step.

5. **Demo app** (needs step 3 first):
   ```powershell
   streamlit run app/streamlit_app.py
   ```
   Pick a division and a forecast week to see the forecast, the persistence baseline, the actual value (when known) and a SHAP explanation. The "what-if" slider changes this week's case count. You can also launch the app from Run and Debug with **Streamlit demo app**.

6. **Tests:**
   ```powershell
   pytest -q
   ```
   Or use the Testing panel (flask icon) in VS Code.

On macOS or Linux, use `python3 -m venv .venv` and `source .venv/bin/activate`. Everything else is the same.

## Method summary

| Step | What is done |
|---|---|
| Problem | One-week-ahead forecast of notified dengue cases per RDHS division |
| Data checks | Completeness, duplicates, divisions summing to the national total, YTD arithmetic, week-to-week correlation of the division pattern |
| Cleaning | Week 24 (division values misaligned, r = 0.04 with the next week) and week 26 (exact duplicate of week 25, as the source itself notes) are masked. The raw data are kept unchanged. |
| Features | 8 features known at week *t*: log cases, own 1-week growth, historical (2023-25) weekly mean, intensity vs history, 2026 YTD weekly rate, cases vs YTD rate, leptospirosis cases, national 1-week growth |
| Target | Log growth `log1p(y[t+1]) - log1p(y[t])`. This is scale-free across divisions and anchored to persistence. Predictions are converted back to cases. |
| Validation | Rolling origin with an expanding window: tune and select on forecasts for weeks 30-31, test on weeks 32-33. Each forecast trains only on earlier weeks. |
| Models | Persistence, 2-week moving average, national-trend naive, Ridge, Random Forest, XGBoost, LightGBM, mean ensemble |
| Metrics | MAE, RMSE, WAPE, R², MAE on log scale, skill vs persistence, national-total error |
| Robustness | 5-seed stability check, and a sensitivity run on the data exactly as printed |
| Explainability | TreeSHAP (beeswarm, bar, dependence, waterfall) and LIME for Colombo's 16 Aug 2026 forecast |
| Output | Genuine forward forecast for the week ending 23 Aug 2026 (`reports/results/forecast_next_week.csv`). The dataset contains no actual value for this week. |

## Limitations (short version)

The history is very short (10 weeks, 2 of them unreliable), and every evaluated week falls in a declining phase of the season. The data are notified cases rather than infections, and there are no climate, vector or population variables. Model explanations show associations, not causes. Details and suggested extensions are in [`docs/dataset_limitations.md`](docs/dataset_limitations.md).
